# DXA QC — технический отчёт финального прототипа

## Постановка задачи и критерии

По [официальному ТЗ](context/TASK_SPEC.md) система принимает DICOM DXA-исследование и выдаёт по изображению/области качество и нарушения. Для позвоночника проверяются укладка, ось (допуск 5°) и посторонние предметы. Для проксимального бедра — укладка с ротацией и область интереса с указанными в ТЗ геометрическими отступами. Восемь полей CSV и целевое время ≤3 минут на исследование заданы в ТЗ. Данный прототип не утверждает, что физические критерии измеряются валидированной геометрической моделью.

## Данные, протокол и утечки

В `Dataset_learn` — 499 DICOM, 100 исходных исследований и 252 уникальных декодированных пиксельных массива. Исходный folder ID хранится отдельно от переписанного StudyInstanceUID; placeholder PatientID не считается идентификатором пациента. Официальные метки source-study-level и nullable: пропуски не превращены в отрицания, качество обучалось как отдельная цель, hip укладка/ротация осталась одной меткой. Группы исследования и дубликатов не пересекают внешние фолды. Семена 17/29/43 и пять групповых фолдов одинаковы для сравнимых QC запусков. Thresholds, calibration, early stopping и выбор модели использовали только outer-train через inner validation. `Dataset_test` и форматные файлы использовались только для загрузки и operation smoke.

## DICOM pipeline и модель

Audited loader принимает single-frame 2-D uint8 MONOCHROME2. DINOv3 Large и MedImageInsight работают локально; конфигурации и hashes приведены в [инвентаре](context/MODEL_INVENTORY.md). E023 линейный anatomy router получает только замороженные признаки. E007 A3 MIL агрегирует признаки внутри study-bag и выдаёт семь компонентных голов (spine ×3, right hip ×2, left hip ×2) плюс три независимые quality heads. Пропущенные target маскируются. Сохранённые temperatures и thresholds применяются после inference. Для hip вывод объединяет правую и левую головы максимумом, потому что сторона неизвестна; этот шаг не означает подтверждённую латерализацию.

Автоматическая группировка использует однозначные DICOM StudyInstanceUID; проверенная карта разрешает переписанные UID. Нечитаемые файлы и ошибки остаются в JSON. CSV минимален, web API показывает те же модельные решения и дополнительные объясняющие поля. [Архитектура](ARCHITECTURE.md), [API](API.md), [руководство](USER_GUIDE.md).

## Результаты и отрицательные проверки

Текущий E007 A3 имеет исторический пяти-классовый source-study proxy macro-F1 0.2469687. Это **не** официальная image-level F1. E010/E011/E014 и E015–E018 не улучшили основной proxy, включая контролируемые scratch/random пары; E019 дал 0.2684301, но парная 95% CI разности с E007 пересекает ноль, а AP и quality ухудшились. E020 внешний descriptor pilot был отрицательным. [Таблица E007–E025](EXPERIMENTS_SUMMARY.md) сохраняет отрицательные результаты и границы сравнения.

Router E023 internal 1.0 balanced accuracy частично круговая: предварительная anatomy mapping использовала то же пространство DINO. На независимых внешних рентгенограммах E024: balanced accuracy .899, 42/208 бедренных изображений направлены в позвоночник; это diagnostic domain shift, не DXA QC. E025 показал: одинаковые результаты двух hip файлов в одном bag — ожидаемое повторение study-level вектора. Все 15 seed/fold replay совпали с сохранёнными предсказаниями; image-level ground truth отсутствует.

## Геометрия, производительность и deployment

Per-image PixelSpacing предпочтителен при наличии; внешняя калибровка supplied scanner не переносится на другие устройства или resized PNG. Нет экспертных landmarks/segmentation для проверки мм/углов. Dockerfile основан на закреплённом CUDA runtime, зависимости закреплены, inference offline при локально смонтированных весах. Порт приложения ограничен loopback за Nginx, uploads живут во временном каталоге. [Инструкция](DEPLOYMENT.md).

Новый benchmark финального образа на целевой конфигурации **не выполнен**: локальный Docker daemon недоступен, сервер по TCP/22 не отвечает. Исторические времена других образов не используются для подтверждения лимита 3 минуты. CPU fallback сохраняет математическую модель, но его скорость требует отдельной проверки.

## Ограничения и дальнейшее развитие

Без независимых экспертных DXA image-level anatomy/QC меток нельзя заявлять клиническую точность. Нужны подтверждение CSV Failure/unknown контракта организаторами, лицензии для распространения весов, независимая DXA проверка router/hip side и landmarks, затем замороженный grouped пилот. Никакие новые ML эксперименты в текущем stop-code релизе не выполнялись. [Полные ограничения](LIMITATIONS.md).
