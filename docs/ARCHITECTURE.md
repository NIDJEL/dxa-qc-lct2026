# Архитектура финального прототипа

1. DICOM loader проверяет single-frame 2-D uint8 MONOCHROME2 и декодирует пиксели. Ошибки попадают в JSON.
2. Группы формируются по непротиворечивому DICOM StudyInstanceUID. Проверенная внешняя карта поддерживает исходные исследования с переписанными UID. Совпадающие декодированные пиксели не могут оказаться в разных группах.
3. Замороженные DINOv3 Large и MedImageInsight формируют по 1024 признака. Их входное преобразование задано в `src/dxa_qc/service.py` и локальном инвентаре моделей.
4. E023 использует эти признаки для маршрута spine/hip. Его вероятность не является клинически откалиброванной уверенностью.
5. E007 A3 агрегирует изображения внутри study-bag и выдаёт десять исходных голов: пять официальных компонентов с раздельными сторонами бедра и три независимых quality target. Отсутствующие метки при обучении маскировались.
6. Сохранённые temperatures и thresholds преобразуют вектор в решения. Сторона бедра остаётся неизвестной; парные правые/левые головы для вывода объединяются максимумом. Качество не вычисляется как OR нарушений.
7. CSV содержит восемь конкурсных полей; JSON хранит вероятности, пороги, grouping, provenance и ошибки. Web API использует тот же inference.

Один вектор E007 повторяется в строках снимков одной группы. Такая строка не является отдельным экспертно подтверждённым image-level диагнозом. Геометрия и физические единицы не выводятся без применимой калибровки и проверенной модели landmarks.
